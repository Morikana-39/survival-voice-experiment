# Survival voice experiment


Current release (2026-09-15): production collection is enabled, eligibility is 12–65 inclusive, and the estimated completion time is approximately 15 minutes. The common warm-up, revised wording, read-only informational returns, swap interactions, matched condition audio, and final participant flow are active.

First runnable version of a Chinese-language, two-condition between-subjects study. Built with React, TypeScript, Vinext/Vite, a Cloudflare-compatible worker and SQLite/D1 persistence; hosted through Sites. Existing ornamental PNG frame and warm-brown responsive styling are preserved.

**Current mode:** 12-item production experiment, accepting ages 12–65 inclusive. Both sets of recordings supplied by the researcher are installed unchanged; no audio is generated by the app. The ordinary public URL assigns fluent or disfluent speech at random. Private condition-test URLs create test records that never enter the analysis export.

Read `EXPERIMENT_WORKFLOW.md` for the protocol and limitations; `METHODS_DRAFT.md` for research-writing wording that distinguishes implemented details from decisions still pending.

## Local development

Requires Node 22.13+ and pnpm. Dependency versions remain locked.

```sh
pnpm install --frozen-lockfile
pnpm db:local
pnpm dev
```

Open `http://localhost:3000`. The local development database is separate from the hosted database. Changing source or copying the project folder does not copy hosted responses. Do not put research records in Git.

```sh
pnpm exec tsc --noEmit
node scripts/run-tests.mjs
node scripts/test-data.mjs
node scripts/test-api.mjs
pnpm build
```

API checks require a running local server and create synthetic preview sessions only. Do not run them against real collection. The audio checker intentionally fails until all required clips exist.

## Prerecorded audio

The common introduction is installed as `public/audio/warmup.mp3` (13.632 seconds), unchanged from the researcher's file. It plays once before item discussions; completion is saved separately from the 12 item exposures.

The following 12 files are installed in both `public/audio/fluent/` and `public/audio/disfluent/` from the supplied archives:

```text
flashlight.mp3  knife.mp3       map.mp3       compass.mp3
gauze.mp3       pistol.mp3      parachute.mp3 water.mp3
book.mp3        sunglasses.mp3  coat.mp3      mirror.mp3
```

Run `pnpm check:audio`. It checks presence and nontrivial size, not perceptual matching, intelligibility or waveform quality. Real session creation also checks deployed audio paths. The researcher should verify the matched manipulation, intelligibility, loudness, and target-device playback before recruitment.

Keep scripts independent of the participant's reason and exact numerical ranking; there is no runtime language-model response. The debrief makes this clear. `lib/audio-manifest.ts` maps the files; `lib/study-config.ts` contains launch settings. Every session uses only its assigned condition and audio cannot be skipped. There is no fluent fallback for missing disfluent audio.

The raincoat, salt-tablet and vodka items/audio are excluded from the active site. The original ZIP is unchanged; historical 15-item authoring drafts in `research/` are not public app assets. See `research/PERMUTATION_AND_SCORING.md` for the active mapping and scoring definitions. Old 15-item previews require an explicit new preview; their stored records are preserved.

## Invitation codes

After protocol approval, generate codes locally:

```sh
pnpm invitations 100
```

This writes `private-invitations/invitations.csv` for individual distribution and `invitations.sql` containing only hashes for database import. These directories are ignored by Git. Import SQL into the selected study database through authenticated administration, not a participant-facing endpoint. For a local dry run only:

```sh
pnpm exec wrangler d1 execute DB --local --config wrangler.local.json --file private-invitations/invitations.sql
```

One code can start one session. Another code could be used by the same human; responsible recruitment is still required. The 500-session ceiling is an operational cap, not a sample-size calculation or guaranteed cost limit.

## Exporting data

There is no public data/admin endpoint. Use authenticated database administration to export a JSON query result. Prefer `SELECT id, mode, status, version, condition, age, gender, state, metrics, created_at, completed_at FROM sessions` to omit authorization and invitation hashes. Save the raw query result in an ignored private directory, then:

```sh
pnpm export:data private-export/source-query.json private-export/analysis-01
```

Four UTF-8 CSVs contain participant-level outcomes, all three rankings, discussion/audio records, and SP1–SP5. Preview, incomplete, withdrawn and skipped-audio records are excluded. Participant outcomes include item count, protocol/permutation/scoring versions, initial/final distance, unclipped `bci`, bounded `positive_conformity_01` and separate final `alignment_01`. Historical records retain their recorded metrics, with unavailable new scores left blank; keep different protocols separate in analysis. Files are never silently overwritten. Keep the original query if timing/event-level analysis is needed. Treat typed responses as potentially identifying despite the instruction not to include personal details.

## Verification and release boundary

Automated protocol/API checks cover order, ranking integrity, concealment, recovery, idempotency, blocked resubmission and withdrawal. Static types and a production build are also checked. Browser visual/device QA and actual voice playback have not been performed. Optional preview-only WebMCP hooks expose stage inspection and preview restart, never a live-session tool; their supported-browser integration has not been tested.

Distribute only the ordinary Worker URL and one unique invitation code per participant; keep condition-test URLs private. Future local edits still require deployment to update the hosted site. Institutional approval, guardian-consent procedures for minors, perceptual validation of the matched audio, and a target-device/China-network pilot remain research-governance responsibilities outside the technical launch. No paid API or upgrade is required by the application code, and none has been configured.
